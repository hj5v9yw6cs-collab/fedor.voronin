# Fedor. — English Studio

Одностраничный сайт репетитора английского: история, шкала уровней,
тест на определение уровня (с чтением и аудированием) и футер со
связью. Дизайн-система (типографика, цвета, фирменная ромашка) построена
по референсу masamadre.ru, адаптирована в тёмной палитре, с переводом
интерфейса на RU/EN.

## Разработка

```bash
npm install
npm run dev
```

## Деплой на GitHub Pages — домен fedorvoronin.ru

Сборка и выкладка настроены через `.github/workflows/deploy.yml` —
срабатывает на каждый пуш в `main`. Домен указан в `public/CNAME`.

**Разово нужно сделать на GitHub:**

1. **Settings → Pages → Source** → выбрать «GitHub Actions».
2. Смёржить эту ветку в `main` (или запушить туда) — соберётся и
   выложится сайт.
3. Там же, в **Settings → Pages → Custom domain**, вписать
   `fedorvoronin.ru` и сохранить. Через пару минут после того, как DNS
   (следующий пункт) настроен и проверен, появится галочка и кнопка
   «Enforce HTTPS» — включить её.

**Разово нужно сделать в reg.ru**, в настройках DNS-зоны домена
(«DNS-серверы и управление зоной» → добавить записи):

| Тип | Хост | Значение |
|---|---|---|
| A | @ (или пусто) | `185.199.108.153` |
| A | @ (или пусто) | `185.199.109.153` |
| A | @ (или пусто) | `185.199.110.153` |
| A | @ (или пусто) | `185.199.111.153` |
| CNAME | www | `<владелец-репозитория>.github.io.` |

(4 A-записи — на них резолвится сам `fedorvoronin.ru`; CNAME на `www`
опционален, но пригодится, если кто-то наберёт `www.fedorvoronin.ru`.)

DNS может применяться от нескольких минут до суток. Пока не применилось,
сайт по служебному адресу `<владелец-репозитория>.github.io/fedor.voronin/`
будет выглядеть сломанным (пути к файлам настроены под корень
`fedorvoronin.ru`, а не под этот подпуть) — это ожидаемо, ждём DNS,
после подключения домена всё встанет на место.

## Тест и отправка результатов на почту

Тест в разделе «Тест» (`src/components/Test.jsx`) в конце отправляет
имя, контакт (telegram/instagram) и результат на
`fedor1349666666@gmail.com` через [FormSubmit](https://formsubmit.co) —
бесплатный сервис «форма → email», работающий без бэкенда, регистрации
и API-ключей.

**Важно:** это не работает через превью-ссылки (Claude Artifacts) — у
них строгая политика безопасности, блокирующая любые запросы на
внешние сайты. Проверять доставку почты можно только на реально
задеплоенном сайте (см. «Деплой» выше).

**Единственное, что нужно сделать после деплоя — один раз подтвердить
адрес:**

1. На сайте кто угодно проходит тест до конца и отправляет результат —
   подойдёт и ваша собственная тестовая попытка.
2. FormSubmit в ответ пришлёт на `fedor1349666666@gmail.com` письмо
   с темой вроде «Confirm form submission on formsubmit.co» и кнопкой
   «Activate Form» — нажмите её (проверьте и папку «Спам»/«Промоакции»).
3. Готово: это письмо было единственным «служебным», сам результат
   теста в нём не отправлялся. Начиная со следующей отправки все
   результаты будут приходить на почту уже как обычные письма,
   без всяких дополнительных подтверждений.

Если запрос по какой-то причине не проходит (нет сети, адрес ещё не
подтверждён и т.п.), у посетителя откроется почтовый клиент с уже
заполненным письмом на `fedor1349666666@gmail.com` — так результаты не
теряются в любом случае.

## Личный кабинет ученика

На сайте есть отдельная страница `/cabinet` (ссылка «кабинет» в шапке и
футере) — туда заходят ученики, которым вы выдали доступ, и видят своё
расписание, ссылку на Яндекс Телемост, домашнее задание, материалы и
ваши комментарии к уроку. У вас как у преподавателя там же — список
учеников и форма, чтобы всё это заполнять.

Это уже не статика — нужна настоящая база данных и вход по паролю,
для этого используется бесплатный сервис
[Supabase](https://supabase.com) (Postgres + аутентификация). Сайт
по-прежнему живёт на GitHub Pages, просто ходит в Supabase по API.

**Разово нужно сделать:**

1. Зарегистрироваться на [supabase.com](https://supabase.com) и
   создать новый проект (Free tier — этого более чем достаточно).
2. В проекте: **SQL Editor → New query** — вставить содержимое файла
   [`supabase/schema.sql`](supabase/schema.sql) из этого репозитория и
   нажать Run. Это создаст таблицы `profiles` (ученики/преподаватель) и
   `lessons` (занятия) со всеми нужными правами доступа.
3. **Settings → API** — скопировать `Project URL` и `anon public` ключ.
4. Добавить их как секреты репозитория: **Settings → Secrets and
   variables → Actions → New repository secret**:
   - `VITE_SUPABASE_URL` — тот самый Project URL;
   - `VITE_SUPABASE_ANON_KEY` — тот самый anon-ключ.

   (Для локальной разработки — скопировать `.env.example` в `.env` и
   вписать туда же эти два значения.)
5. Запушить/смёржить в `main` — сайт пересоберётся уже со включённым
   кабинетом.
6. **Добавить себя как преподавателя:** зайти на сайт → «кабинет» →
   войти нельзя, аккаунта ещё нет. Сначала создайте свой аккаунт в
   Supabase: **Authentication → Users → Add user** — укажите свою
   почту и пароль. Он автоматически появится в таблице `profiles` как
   `student` — переключите себя на `teacher` в **SQL Editor**:
   ```sql
   update profiles set role = 'teacher' where id =
     (select id from auth.users where email = 'ваша-почта@example.com');
   ```
7. **Добавить ученика:** так же — **Authentication → Users → Add
   user**, указать его почту и пароль, и сообщить эти данные ученику
   (например, в Telegram). Роль `student` присваивается автоматически,
   ничего больше делать не нужно — ученик появится у вас в кабинете в
   списке учеников.

Если секреты `VITE_SUPABASE_URL`/`VITE_SUPABASE_ANON_KEY` не заданы,
раздел «кабинет» просто покажет заглушку «пока не настроен» — на
остальной сайт это никак не влияет.

(Технически: прямой переход или обновление страницы на `/cabinet`
работает на GitHub Pages благодаря `public/404.html` — у статического
хостинга нет своего роутинга, этот файл перенаправляет такие ссылки
обратно на `index.html`, где React уже сам показывает нужную
страницу.)
